# Governance

MODENA is maintained by [@ricardoleal20](https://github.com/ricardoleal20).
It currently uses a single-maintainer model. There is no steering committee,
elected board, or guaranteed review schedule.

## Decisions and contributions

Use [issues](https://github.com/ricardoleal20/modena/issues) to discuss substantial
changes and [pull requests](https://github.com/ricardoleal20/modena/pulls) to
review implementations. Anyone may propose a change, report a problem, or
provide reproducible evidence. Follow the [contribution guide](CONTRIBUTING.md)
and [code of conduct](CODE_OF_CONDUCT.md).

The maintainer makes final decisions on scope, architecture, compatibility,
merges, and releases after considering the discussion and evidence. Proposals
should explain the user or scientific need, alternatives, limitations, and
how the result can be checked. Scientific claims need appropriate independent
evidence; popularity or a passing smoke test alone does not establish accuracy.

When a proposal is declined or deferred, the issue or pull request is the place
to record the rationale. Contributors may ask for reconsideration with new
evidence. Disagreements should address the technical reasoning and remain
respectful. Repository ownership and access are managed by the maintainer.

## Releases and project direction

The maintainer determines release timing and documents user-visible changes
and known limitations. Early development APIs and input formats may change.
Release evidence should identify the revision, environment, checks that ran,
and checks that were skipped; CI configuration alone is not a completed run.

Contributors retain copyright in their contributions and submit them under
the project's [MIT license](LICENSE). Contribution does not automatically
grant merge or release permissions. Additional maintainers or a different
governance model may be proposed through an issue and documented here if
adopted. This document describes the current model, not a succession or
long-term availability guarantee.
