# Verification for MODENA 0.1.1

Checks performed on 22 October 2026 on macOS arm64. The release candidate starts
from scientific-hardening commit `8e8f79f` and includes the changes listed in
the [changelog](../../CHANGELOG.md). The existing scientific implementation was
retained; its earlier verification is a separate historical record.

Main tests used Rust 1.97.1 and Python 3.12. The minimum-compiler checks used
Rust 1.90.0. Raw command logs and return codes are under
[`v0.1.1-checks/`](v0.1.1-checks/). These checks ran on the candidate working
tree before the release commit; records identify that state explicitly.
The [source manifest](v0.1.1-checks/source-manifest.json) identifies the tested
code and build metadata by SHA256. Compiled binaries are not committed.

## Reproduce

From a source checkout, with Rust 1.90 or newer and Python 3.11 or newer:

```bash
cargo build --locked --release --bin modena
cargo test --locked --workspace
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
MODENA_BINARY="$PWD/target/release/modena" python3 -m unittest discover -s python/modena/tests -v
python3 -m unittest discover -s bench/tests -v
cargo build --locked --release -p modena-core --example scientific_validation
python3 bench/validate.py --output target/scientific-smoke
```

The recorded local commands use temporary build directories and `--offline`
because dependencies were already cached. Fresh installations need registry
access. Optional MPI checks require an MPI installation and local socket access;
GPU execution checks require a suitable adapter.

## Interpretation

These are regression and bounded numerical checks, not a benchmark campaign or
a claim of converged liquid properties. The release does not establish general
performance parity with LAMMPS or production readiness for every exposed model.
See [validation scope](../VALIDATED_SCOPE.md) for the remaining scientific gaps.

The public-source preparation scanned the 737 blobs reachable through the
scientific-hardening baseline for common credential patterns and sensitive
filenames, without matches.

Remote CI status belongs to the GitHub run for the release commit; local
success is not reported as remote CI success.
